# 구름사이

현재 위치의 날씨를 보여 주는 데서 끝나지 않고, **도착할 시간의 예보를 비교해 활동하기 좋은 도시와 이동 경로를 제안하는 서비스**입니다.

Vue.js 수업에서는 날씨 카드, 검색, Router, Pinia, Axios를 각각 실습했습니다. 카드만 만들었을 때는 사용자가 날씨를 확인한 뒤 다시 판단해야 했습니다. 그래서 “정해진 시간 안에서 날씨가 더 나은 곳으로 움직일 수 있을까?”를 서비스의 질문으로 정하고 수업 예제를 하나의 흐름으로 연결했습니다.

- 배포: <https://agenticlab-sh.github.io/skala-vue/>
- 구현 과정: 배포 화면의 `구현 과정`
- 수업 실습: 배포 화면의 `수업 실습 기록`

## 주요 기능

1. 출발 도시, 활동, 출발 시각, 최대 이동 시간을 정합니다.
2. 이동 가능한 도시의 도착 예상 시각을 계산합니다.
3. 도착 시각과 가까운 예보를 찾아 활동 적합도를 비교합니다.
4. 추천 도시, 후보 도시, 3시간·6시간 뒤 출발 결과를 보여 줍니다.
5. OSRM 경로 좌표를 지도에 그리고 목적지 주변 건물을 3D로 표시합니다.
6. 관심 도시와 온도 단위, 마지막 출발 조건을 저장합니다.
7. 목적지나 도시의 날씨가 비·흐림·안개·눈이면 화면 효과로 구분하고 필요할 때 끕니다.
8. 전국 28개 대표 지점의 현재 날씨를 한 지도에서 비교하고 비·흐림 지역만 골라 봅니다.

활동마다 비, 기온, 바람, 습도의 허용 범위를 다르게 두었습니다. 점수만 표시하지 않고 강수확률, 기온, 이동 시간, 추천 이유를 함께 보여 줍니다.

## 화면 구성

| 경로 | 내용 |
| --- | --- |
| `/` | 조건 입력, 목적지 추천, 실제 경로 지도, 후보·시간 비교 |
| `/weather/search` | 도시 현재 날씨 검색과 관심 도시 |
| `/weather/:cityId` | 시간대별 예보와 일출·일몰 상세 |
| `/process` | 구현 과정, 수업 개념 적용, 데이터 흐름, 실패와 한계 |
| `/challenges` | PDF 72~270쪽 코드 챌린지 13개 |

`/about`은 기존 링크가 끊기지 않도록 `/process`로 이동합니다. GitHub Pages에서는 새로고침 후에도 경로를 유지하기 위해 Hash Router를 사용했습니다.

## 데이터와 지도

공개 배포는 키가 필요 없는 Open-Meteo 예보를 사용합니다. 로컬 `.env.local`에 개인 키가 있으면 수업에서 사용한 OpenWeather 현재 날씨와 5일 예보로 전환합니다.

```env
VITE_OPENWEATHER_API_KEY=발급받은_키
```

- Open-Meteo / OpenWeather: 현재 날씨와 시간대별 예보
- OSRM: 도로 거리, 예상 시간, GeoJSON 경로
- SunriseSunset.io: 도시 상세의 일출·일몰
- MapLibre GL JS + OpenFreeMap: 경로 지도와 3D 건물

OpenWeather와 Open-Meteo의 응답 형식이 달라 요청 직후 `temperature`, `humidity`, `windSpeed`, `precipitationProbability`, `time`으로 정리했습니다. 추천 코드는 어떤 제공자를 사용했는지 알 필요가 없습니다.

지도는 실제 도로 이동선을 보여 주지만 건물 그림자를 계산하지는 않습니다. [ShadeMap](https://shademap.app/help/)처럼 건물 높이와 태양 위치로 그늘을 계산하는 서비스에서 문제의 방향을 참고했고, 이번 제출에서는 날씨에 따른 도시 선택과 3D 경로 확인까지 구현했습니다.

날씨 효과는 추천 목적지의 도착 시각 예보와 도시 상세의 현재 예보를 그대로 사용합니다. 강수확률을 빗줄기 세기로 바꾸지 않고 `약한 비`, `강한 비`처럼 API가 준 상태 문구로 밀도를 나눴습니다. 흐림·안개·눈도 서로 다른 형태로 표시하며 상단 버튼에서 끌 수 있습니다. 감소된 모션 환경에서는 움직이는 입자를 없애고 정적인 상태만 남깁니다.

화면 효과와 지도 날씨는 역할을 나눴습니다. 화면 효과는 현재 보고 있는 한 도시의 분위기를 표현하고, 지도에서는 Open-Meteo의 현재 기온·강수량·운량을 전국 28개 대표 지점에 표시합니다. `전체 날씨`, `비 오는 지역`, `흐린 지역`을 전환할 수 있고 지점을 누르면 실제 값을 확인할 수 있습니다. 행정구역 전체나 기상 레이더 강수대를 그린 것은 아니므로 지도 아래에도 지점별 모델값이라는 점을 밝혔습니다.

## 수업 내용 적용

### 반응형 상태와 계산 속성 — 126·144쪽

출발지, 활동, 시간은 `ref`로 관리하고 선택 도시와 추천 문구는 `computed`로 계산했습니다. API 요청과 점수 계산은 `useTripPlanner` composable로 옮겨 view는 입력과 상태 표시에 집중했습니다.

### 컴포넌트 — 146~177쪽

입력, 대표 추천, 후보 도시, 시간 비교, 경로 지도를 나눴습니다. 부모 화면은 props로 값을 전달하고 `update:`와 `submit` emit으로 변경을 받습니다. 슬롯, provide/inject 실습은 서비스 코드에 억지로 넣지 않고 `수업 실습 기록`에 보존했습니다.

### Router와 Pinia — 178~211쪽

서비스와 학습 기록을 경로로 분리하고 도시 상세는 동적 경로로 만들었습니다. 검색어는 query에 남기고, 온도 단위·관심 도시·마지막 조건은 Pinia와 localStorage에 저장했습니다.

### Axios와 UI 라이브러리 — 212~273쪽

도시별 날씨는 동시에 요청하고 `Promise.allSettled()`로 일부 실패를 허용했습니다. Element Plus는 실제로 쓰는 컴포넌트만 등록해 주 JavaScript 번들을 약 942kB에서 325kB로 줄였습니다. MapLibre는 추천 결과 뒤에 지연 로드해 다른 화면의 초기 로딩과 분리했습니다.

## 트러블 슈팅

### 공개 화면에서 OpenWeather 키를 사용할 수 없었습니다

처음에는 GitHub Actions Secret을 사용하면 안전하다고 생각했습니다. 하지만 Vite 환경 변수는 최종 JavaScript에 포함되므로 브라우저에서 키를 확인할 수 있습니다. 공개 배포는 Open-Meteo로 바꾸고, 개인 키는 로컬에서만 사용하도록 나눴습니다.

![초기 OpenWeather 키 누락 화면](docs/weather-api-key-missing.jpg)

### 경로 API 실패가 추천 전체를 막았습니다

날씨 결과를 받은 뒤 OSRM 요청 하나가 실패하면 추천도 사라졌습니다. 경로 요청 안에서 오류를 처리하고 직선거리 기반 시간과 추정선을 반환하도록 바꿨습니다. 실제 경로와 추정값은 결과 아래에 구분해 표시합니다.

### 빠르게 조건을 바꾸면 이전 결과가 다시 나타났습니다

먼저 시작한 요청이 늦게 끝나 새 결과를 덮는 경우가 있었습니다. composable에 요청 번호를 두고 가장 최근 요청만 상태를 변경하도록 수정했습니다.

### 3D 건물이 콘솔 오류로 보이지 않았습니다

`fill-extrusion-base` 안에 중첩한 `zoom` 조건이 MapLibre 표현식 규칙에 맞지 않았습니다. zoom은 건물 높이를 보간하는 최상위 표현식에서만 사용하고, 바닥 높이는 데이터의 `render_min_height`를 바로 읽도록 고쳤습니다. 수정 후 2D/3D 전환과 콘솔을 다시 확인했습니다.

### 지도 실패가 페이지 전체 실패가 될 수 있었습니다

지도는 날씨 추천과 다른 외부 자원입니다. 타일 또는 WebGL을 불러오지 못해도 추천 결과는 유지하고 출발지, 목적지, 거리, 시간, 경로 출처를 글로 남기도록 했습니다.

### 흐림 효과가 회색 배경처럼만 보였습니다

첫 화면에서는 구름과 기본 배경의 명도가 비슷해서 흐림인지 단순한 배경색인지 구분하기 어려웠습니다. 실제 화면을 확인하면서 구름층의 명암과 흐림 정도만 조정했습니다. 비·눈 입자는 콘텐츠를 클릭하는 데 방해되지 않도록 별도 오버레이에 두고, 효과를 껐을 때는 DOM에서도 제거되게 했습니다.

### 지도를 움직여도 비 오는 지역이 보이지 않았습니다

처음 만든 비 효과는 추천 목적지 한 곳의 상태를 화면 위에 보여 주는 기능이었습니다. 지도 좌표와 연결되지 않아 지도를 확대하거나 축소해도 비가 오는 곳을 찾을 수 없었습니다. Open-Meteo에 전국 대표 지점 좌표를 한 번에 요청하고, 받은 강수량·운량을 MapLibre 레이어와 목록에 함께 연결했습니다. 화면 효과와 혼동하지 않도록 날씨 지도에서는 전체 화면 효과도 잠시 숨겼습니다.

## 디자인 기준

Apple의 [Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/liquid-glass)와 [Materials](https://developer.apple.com/design/human-interface-guidelines/materials) 지침에서 기능 계층과 콘텐츠 계층을 분리하는 원칙을 참고했습니다. 유리 효과는 상단 탐색과 지도 조작에만 사용하고, 읽는 내용은 불투명한 면과 선으로 구성했습니다. 모든 카드를 투명하게 만들거나 의미 없는 색 막대를 추가하지 않았습니다.

지도 구현은 [OpenFreeMap Quick Start](https://openfreemap.org/quick_start/), [MapLibre 3D Buildings 예제](https://maplibre.org/maplibre-gl-js/docs/examples/display-buildings-in-3d/), [OSRM Route API](https://project-osrm.org/docs/v5.22.0/api/)를 기준으로 작성했습니다. OpenFreeMap과 OpenStreetMap 출처는 지도에 표시됩니다.

## 실행과 검증

Node.js 20.19 이상 또는 22.12 이상이 필요합니다.

```bash
npm install
npm run dev
```

제출 전에는 다음 명령을 실행합니다.

```bash
npm run format
npm run lint
npm run build
npm run build:staging
npm run build:production
npm run preview
```

기본 추천과 창원·바다 조건, 2D/3D 지도 전환, 전국 28개 지점의 전체·비·흐림 보기, `/process`, `/challenges` 13개 구역, `/about` 이전 링크, 404를 확인했습니다. 320·390·768·1440px, 200% 확대, 키보드 포커스, reduced motion, 콘솔 오류도 배포 전 검증 항목으로 두었습니다.

예보와 이동 시간은 계획을 돕는 참고 정보입니다. 제주 항공 이동과 API 실패 시 경로는 추정값이며 화면에 출처를 표시합니다.
