# 날씨의 요정

현재 날씨를 보여 주는 데서 끝나지 않고, 도착할 시간의 예보와 활동 장소를 비교해 이동할 곳을 추천하는 Vue 3 과제입니다. 수업에서 따로 실습한 Vue 문법, Router, Pinia, Axios, Element Plus를 하나의 서비스 흐름으로 연결했습니다.

## 만들게 된 이유

처음에는 서울·수원·창원·부산의 현재 날씨를 카드로 보여 주었습니다. 카드를 확인한 뒤 어디로 갈지는 다시 판단해야 했기 때문에, “정해진 시간 안에서 활동하기 나은 곳을 찾을 수 있을까?”를 다음 문제로 정했습니다.

출발 도시와 시간을 입력하면 이동 가능한 도시의 도착 예보를 비교하도록 확장했습니다. 이후 러닝·등산·바다·풋살·자전거가 같은 장소를 추천하지 않도록 활동별 장소를 나누고, 경로와 다른 출발 시간까지 한 화면에서 확인하게 만들었습니다.

## 생각을 구체화한 순서

1. 도시 날씨 카드만으로는 어디로 갈지 정하기 어려워 출발 시각과 이동 시간을 받는 추천으로 바꿨습니다.
2. 활동을 바꿔도 같은 곳이 나오는 문제를 확인해 18개 도시의 러닝·등산·바다·풋살·자전거 장소를 따로 정리했습니다.
3. 멀리 이동하는 경우만 보지 않도록 출발 도시도 후보에 남겼습니다. 같은 도시를 고르면 시청·도청·군청에서 실제 활동 장소까지의 경로를 계산합니다.
4. 시간과 건물 높이로 그림자를 보여 주는 그늘길에서 아이디어를 얻었습니다. 도착 시각의 그림자를 3D 지도에 표시하고, OSRM 경로 대안의 그늘 비율과 추가 시간까지 비교했습니다.
5. 직접 화면을 눌러 보며 점수·건물 수·중복 API 정보는 덜어냈습니다. 대신 빠른 설정, 탐색 상태, 앞뒤 출발 시간과 지도 각도처럼 실제 선택에 필요한 조작을 더 분명하게 만들었습니다.

## 주요 기능

1. 출발 도시·시각·30분~5시간의 최대 이동 시간과 활동을 입력해 목적지를 비교합니다. 아침·오후·저녁으로 구분한 서울·창원·광주 예시를 누르면 조건이 채워지고 활동 선택으로 이어집니다.
2. 출발 지역을 포함해 이동 시간 안의 전체 후보를 대표 추천 옆에 보여 주고, 선택한 장소의 추천·지도·시간 비교를 갱신합니다.
3. OSRM 경로와 추정 경로를 구분하고 MapLibre 지도에 이동선과 3D 건물을 표시합니다. 같은 도시에서는 행정청사에서 활동 장소까지의 지역 내 경로를 사용합니다. 목적지 3D에서는 건물 그림자와 경로 대안을 확인하고, 나침반 회전과 지도 기울기를 직접 조절할 수 있습니다.
4. 도시별 날씨는 시·도 권역과 검색어로 범위를 좁힐 수 있습니다. 시간대별 예보, 일출·일몰, 관심 도시와 온도 단위도 제공합니다.
5. 48개 기준 지역의 144개 기상 지점과 비·흐림 상태를 지도에서 확인합니다. 비와 구름 모션은 콘텐츠를 덮지 않고 각 지도 좌표와 페이지 배경에서만 움직입니다.
6. 기준 시각보다 1·2·3시간 빠른 경우와 늦은 경우 여섯 가지를 한 시간 간격으로 비교합니다. 접속과 새로고침 때는 약 2초 환영 화면을 보여 줍니다. 추천 요청 중에는 투명 유리 레이어의 지도 탐색 애니메이션을 한 번 끝까지 보여 주되, 실제 비교 작업이 더 오래 걸리면 마지막 장면을 유지합니다.

## 내가 직접 확장한 부분

- 현재 날씨 카드에서 도착 예상 시각의 예보를 비교하는 이동 추천으로 확장했습니다.
- 18개 도시에 활동별 장소를 따로 두었습니다. 출발 도시도 후보에서 제외하지 않으며, 이동 시간 안에 남은 후보를 전부 보여 줍니다. 추천 점수는 날씨 82%와 장소 적합도 18%를 합친 뒤 이동 시간을 반영하며, 바다는 해안 장소가 있는 도시만 비교합니다.
- OSRM 요청이 실패해도 직선거리 기반 시간과 추정선을 남겨 날씨 추천을 계속 볼 수 있게 했습니다.
- 그늘길의 문제 설정에서 한 단계 더 나아가, 도착 시각의 태양 고도·방위와 지도 건물 높이로 그림자를 계산해 3D 지도에 표시했습니다. OSRM 경로 대안이 여러 개면 표시 구간의 그늘 비율과 추가 시간을 함께 비교합니다.
- 전국 48개 기준 지역을 중심권·북동권·남서권의 144개 지점으로 나눠 현재 강수량과 운량을 지도에 표시했습니다. 이 값은 행정구역 경계나 기상 레이더가 아닌 비교용 모델 지점입니다.
- 온도 단위, 관심 도시, 마지막 출발 조건, 날씨 효과 설정을 Pinia와 `localStorage`에 저장했습니다.
- 활동 장소의 좌표는 OpenStreetMap Nominatim으로 한 번 확인한 뒤 정적 데이터로 보관했습니다. 서비스를 사용할 때 좌표 검색 API를 반복 호출하지 않습니다.

## 트러블슈팅

### OpenWeather 키를 공개하지 않고 실제 예보를 연결했습니다

처음에는 GitHub Actions Secret이면 브라우저에서도 키가 보이지 않을 것으로 생각했습니다. 하지만 `VITE_` 환경 변수는 빌드 결과에 포함될 수 있었습니다. 배포 작업이 OpenWeather 현재·5일 예보를 먼저 받아 키가 빠진 JSON으로 만들고, Vue 화면은 그 파일만 읽도록 바꿨습니다. production 빌드와 생성 파일을 다시 검색해 실제 키가 없는지 확인했습니다. 프론트엔드 환경 변수는 비밀 저장소가 아니라는 점을 배웠습니다.

![OpenWeather 키가 없을 때 확인한 초기 화면](docs/weather-api-key-missing.jpg)

### 경로 API 실패가 추천 결과까지 지웠습니다

OSRM 요청이 실패하면 전체 흐름이 중단됐습니다. `requestDrivingRoute()` 내부에서 실패를 처리하고 직선거리 기반 추정값을 반환하도록 수정했습니다. 지도 요청을 차단한 상태에서도 추천 카드와 텍스트 경로가 남는지 확인했습니다. 외부 API마다 실패 범위를 나눠야 한다는 점을 배웠습니다.

### 이전 요청이 최신 결과를 덮었습니다

활동을 빠르게 바꾸면 먼저 시작한 요청이 늦게 끝나 새 결과를 덮는 경우가 있었습니다. `useTripPlanner()`에 요청 번호를 두고 가장 최근 실행만 상태를 갱신하게 했습니다. 조건을 연속으로 바꾼 뒤 마지막 활동의 장소와 점수가 남는지 확인했습니다. 비동기 요청은 완료 순서가 실행 순서와 다를 수 있다는 점을 확인했습니다.

### MapLibre 레이어가 콘솔 오류로 표시되지 않았습니다

건물 높이와 기상 지점 투명도 식에서 `zoom`을 잘못 중첩했습니다. 확대 보간을 표현식 바깥으로 옮기고 건물 바닥 높이는 데이터 값을 바로 읽게 수정했습니다. 2D/3D 전환과 비·흐림 지점 수를 다시 비교하고 콘솔 오류가 없는지 확인했습니다. 지도는 source, layer, expression의 역할을 나눠 확인해야 디버깅하기 쉬웠습니다.

### 그늘이 있어도 경로를 비교할 수 없었습니다

처음에는 3D 건물과 그림자만 그리면 경로를 고를 수 있다고 생각했습니다. 하지만 한 경로만 요청한 상태에서는 비교 대상이 없었습니다. OSRM 요청에 경로 대안을 추가하고, 각 경로에서 현재 지도 안에 들어온 좌표를 표본으로 뽑아 그림자 안에 있는 비율을 계산했습니다. 10분을 더 이동하려면 그늘이 15%p 이상 늘어야 선택되도록 추가 시간 감점도 넣었습니다. 대안이나 건물 높이 데이터가 없을 때는 억지로 결과를 만들지 않고 빠른 경로를 유지하게 했습니다.

### 그림자를 계산했지만 지도에서 알아보기 어려웠습니다

처음 그림자 레이어는 그늘 경로를 고른 뒤에만 켜졌고 지도색과 비슷해 잘 보이지 않았습니다. 목적지 3D를 열 때도 도착 시각의 그림자를 계산하도록 공통 흐름으로 묶고, 건물 아래의 그림자 면을 더 짙게 조정했습니다. 지도 안에는 계산 기준 시각을 작은 범례로 남겼습니다. 지도 종류는 이동 경로와 전국 날씨만 먼저 보여 주고 비·흐림 필터는 날씨 지도를 연 뒤 나타나게 바꿨습니다.

태양각 단위도 다시 확인했습니다. 사용 중인 SunCalc 2.0.1은 고도와 북쪽 기준 방위각을 이미 도 단위로 반환하므로 별도 변환을 넣지 않았습니다. 같은 시각의 실제 반환값과 지도 범례를 비교한 뒤 그림자 색과 외곽선만 조정했습니다.

### 같은 도시를 선택하면 경로가 거의 보이지 않았습니다

처음에는 도시마다 대표 좌표 하나만 있어 서울에서 서울을 선택하면 출발지와 도착지가 같은 점이었습니다. 출발 좌표는 각 지역의 시청·도청·군청으로 정하고, 도착 좌표는 선택한 활동 장소로 분리했습니다. 서울 러닝 예시에서 서울시청에서 여의도한강공원으로 가는 OSRM 요청이 발생하는지 브라우저 네트워크에서 확인했습니다.

### 탐색 애니메이션을 넣었지만 사용자가 보기 전에 사라졌습니다

추천 요청이 빠르게 끝나거나 결과 영역이 화면 아래에 있으면 로딩 애니메이션이 있어도 보이지 않았습니다. 기존 결과를 지우지 않고 화면 중앙에 고정된 투명 유리 레이어를 별도로 띄웠습니다. 처음 접속할 때 자동으로 받는 예보에는 이 레이어를 띄우지 않고, 사용자가 추천을 요청했을 때만 나타나도록 분리했습니다.

원본 웰컴 애니메이션은 약 8.2초, 지도 탐색은 약 5초라 팝업 시간과 맞지 않았습니다. 처음에는 플레이어의 `ready` 시점을 재생 완료로 잘못 판단해 모션이 끝나지 않고 제한 시간까지 남는 현상도 있었습니다. 실제 파일이 로드된 뒤 재생을 시작하고 `complete`를 기다리도록 고쳤습니다.

웰컴은 약 1.6초, 지도는 약 1.6초에 한 번 완주하도록 재생 속도를 조정했습니다. 웰컴은 마지막 장면이 그려진 다음 닫고, 지도는 API 작업과 한 사이클 재생을 함께 기다립니다. 작업이 더 오래 걸리면 반복 재생 대신 마지막 장면을 유지해 결과가 준비되는 즉시 닫히게 했습니다. 재생 오류가 생긴 경우에는 최대 대기 시간으로 빠져나오도록 했습니다.

### 출발 시간을 늦추는 선택만 있었습니다

처음에는 현재·3시간 뒤·6시간 뒤만 보여 줘서 비를 피하려고 조금 일찍 출발하는 경우를 비교할 수 없었습니다. 기준보다 1·2·3시간 빠른 세 경우와 1·2·3시간 늦은 세 경우로 바꾸고, 카드 안에는 도착 시각·비·기온만 남겼습니다.

### 비와 구름이 지도를 가리고 실제 지역을 알기 어려웠습니다

넓은 장식 효과로 시작해 지도 배율을 바꿔도 어느 지역의 날씨인지 구분하기 어려웠습니다. 전국 48개 기준 지역을 144개 작은 지점으로 나누고, 지점 좌표를 따라 짧은 빗줄기와 작은 구름이 움직이게 했습니다. 본문 날씨 효과는 카드 위가 아니라 배경 계층으로 내려 글과 버튼을 가리지 않게 했습니다.

### 조작할 수 있는 부분이 설명처럼 보였습니다

외부 날씨 비교, 빠른 설정과 지도 각도가 대표적이었습니다. 접힌 패널 전체에 열기 동작과 포커스 상태를 주고, 빠른 설정에서는 분위기 문구를 빼 도시·시각·이동 시간만 남겼습니다. 지도에는 현재 회전·기울기 값을 보여 주는 조작을 추가했습니다. 개발 중 확인하던 점수, 건물 수, API 갱신 문구는 최종 화면에서 제거했습니다.

### OpenWeather의 한국어 설명이 자연스럽지 않았습니다

예보에 `온흐림`, `튼구름`, `실 비`처럼 일상에서 쓰지 않는 번역이 섞여 있었습니다. API의 한국어 설명을 그대로 출력하지 않고 `흐림`, `구름 많음`, `약한 비`로 정리하는 함수를 추가했습니다. 기존 예보 파일을 읽을 때와 새 예보 파일을 생성할 때 모두 같은 규칙을 적용해 어느 경로로 데이터를 받아도 문구가 같게 했습니다.

### 전국 날씨 요청이 막히자 지도 모션도 모두 사라졌습니다

전국 144개 지점을 네 묶음으로 나눠 Open-Meteo에 동시에 요청했는데, 공개 화면에서 네 요청이 모두 `429 Too Many Requests`로 실패했습니다. 추천에 사용하는 OpenWeather 파일은 정상이어도 전국 지도는 0곳이 되어 비와 구름 모션을 만들 수 없었습니다.

배포 때 한 시간마다 갱신하는 OpenWeather 18개 도시의 현재값을 전국 지도에서도 사용하도록 바꿨습니다. 각 표시 지점은 가장 가까운 기준 도시의 기온·강수·운량을 연결합니다. 추천과 지도가 같은 파일을 읽게 해 방문자 수나 외부 호출 제한에 따라 빈 지도가 되지 않는지, 144개 지점과 날씨 모션이 함께 복구되는지 확인했습니다.

더 자세한 기록은 배포 화면의 [구현 기록](https://agenticlab-sh.github.io/skala-vue/#/process)에 남겼습니다.

## 활용자료

- [그늘길](https://project-g-seven.vercel.app/): 시간과 건물 높이로 그림자를 지도에 보여 주는 문제 설정을 참고했습니다. 화면이나 코드를 가져오지 않았고, 날씨의 요정은 도착 시각의 그림자와 OSRM 경로 대안을 직접 비교하는 기능으로 확장했습니다.
- OpenWeather는 배포용 현재·예보 스냅샷과 전국 지도 기준값에 사용했습니다.
- OSRM은 자동차 이동선과 이동 시간, MapLibre GL JS와 OpenFreeMap은 경로·건물·기상 레이어 표시에 사용했습니다.
- OpenStreetMap Nominatim은 활동 장소 좌표를 한 번 확인하는 데만 사용했고, 확인한 좌표는 정적 데이터로 보관했습니다.
- SunCalc는 도착 시각의 태양 고도·방위 계산, SunriseSunset.io는 일출·일몰 대체 데이터에 사용했습니다.
- LottieFiles의 [Map Animation](https://lottiefiles.com/free-animation/splash-oOdsOknPhV)은 경로·날씨 탐색 중 상태에, [Wellcome Animation](https://lottiefiles.com/free-animation/wellcome-animation-9cXI8Bc0SU)은 접속·새로고침 뒤 환영 화면에 사용했습니다. 두 파일은 [Lottie Simple License](https://lottiefiles.com/page/license)를 확인했습니다.

## 실행 방법

Node.js `20.19+` 또는 `22.12+`가 필요합니다.

```bash
npm ci
npm run weather:sync # OPENWEATHER_API_KEY 환경 변수가 있을 때 예보 파일 생성
npm run dev
npm run build
```

로컬에서는 먼저 `npm run weather:sync`로 예보 파일을 만듭니다. `main`에 push하면 GitHub Actions가 Secret의 키로 OpenWeather 예보를 갱신한 다음 production 빌드를 GitHub Pages에 배포합니다. 한 시간마다 같은 작업을 실행해 공개 예보 파일을 다시 만듭니다.

## 제출 전 확인

- `npm run lint`, 기본·staging·production 빌드 통과
- 홈·도시별 날씨·도시 상세·구현 기록·사용한 프롬프트·수업 실습·활용자료·404 경로 확인
- 320·390·768·1440px, 200% 확대, 키보드와 reduced motion 확인
- 공개 저장소와 Pages의 최신 커밋 일치 확인
- 현재 파일, Git 이력과 `dist`에 실제 API 키가 없는지 확인

예보와 이동 시간은 계획을 돕는 참고 정보입니다. 제주 이동과 API 실패 시 경로는 추정값입니다. 그늘 우선은 도착지 주변 현재 지도에 로드된 건물과 자동차 경로 대안을 비교한 결과이며 보행 안전이나 전체 이동 구간의 그늘을 보장하지 않습니다. 활동 장소의 운영 시간·예약·혼잡도도 출발 전에 별도로 확인해야 합니다.
